# ПОС

ИДЗ №2

Используется C# .NET 10

## Запуск

```bash
dotnet restore ihw2.sln
dotnet run --project Pos
dotnet test ihw2.sln
```

По умолчанию ведомость живёт до конца запуска. Файл ведомости подключается так:

```bash
dotnet run --project Pos -- --data gradebook.json
```

Если файла ещё нет, программа начинает с пустой ведомости и создаёт его при первом изменении. Следующий запуск с тем же путём читает сохранённые данные.

## Ввод из файла

```bash
dotnet run --project Pos -- --input demo-input.txt
```

`demo-input.txt` добавляет двух студентов и два критерия, исправляет оценку,
отклоняет 12 баллов из 10, ставит остальные оценки, отменяет одну и экспортирует
итог. Пока у Анны только 8 из 10 за задания, итог 32%, а результат по выставленной
части 80%. После 15 из 20 за проект итог Анны 77%. У Ильи после отмены проекта
остаётся 36%.

Команда 10 создаёт `demo-results.csv`. Разделитель - точка с запятой, дробная
часть - точка, кодировка UTF-8. Существующий файл программа не перезаписывает:
перед повторным прогоном его нужно убрать. Отсутствующий файл ввода даёт
сообщение и код выхода 1.

## Правила учёта

- Номер студента и номер критерия - положительные целые, каждое уникально
  в своём списке. Одинаковые имена допустимы: это разные люди или разные
  критерии. Пустое имя не принимается, пробелы по краям снимаются.
- Максимум и вес критерия больше нуля. Балл от 0 до максимума включительно.
  При вводе разрешены точка и запятая.
- Оценку можно выставить только существующему студенту и только по критерию
  из рубрикатора. Повторный ввод той же пары заменяет балл, а не создаёт
  вторую оценку. Балл вне диапазона не меняет уже записанное значение.
  Отмена освобождает пару.
- Итог не хранится. Его считает `GradeCalculator` по текущему рубрикатору
  и текущим оценкам. Доля критерия - балл / максимум, затем доли усредняются
  по весам: `100 × Σ(вес × доля) / Σ(вес)`. Веса относительные: 2 и 3 дают
  те же доли, что 40 и 60.
- В итог входят все критерии. Пропущенная оценка даёт нулевой вклад.
  Промежуточный результат берёт только выставленные критерии; явно поставленный
  ноль остаётся оценкой. Пустой рубрикатор и промежуточный результат без
  оценок не получают процент. Готовый процент округляется до двух знаков.
- Студентов и критерии можно добавлять и смотреть. Отдельных команд
  изменения и удаления для них нет.
- Неверный формат ввода вызывает повторный запрос. Конец ввода завершает
  программу; недописанная команда ничего не добавляет. Отказ домена печатает
  причину и возвращает в меню.

## Как устроено решение

- [Domain](Pos/Domain): `Student` и `Criterion` - студенты и критерии с номерами.
  `Evaluation` - оценка. `Gradebook` хранит ведомость одного курса.
  `GradeCalculator` считает итог, `FinalGradePolicy` и `ProgressGradePolicy`
  выбирают, какие критерии в него входят.
- [PosFacade](Pos/Application/PosFacade.cs): сценарии меню. Загружает ведомость,
  вызывает домен и сохраняет изменение или отдаёт итог на экспорт.
- [IGradebookRepository](Pos/Application/IGradebookRepository.cs): порт хранения.
  [Память](Pos/Adapters/Persistence/InMemoryGradebookRepository.cs) держит одну
  ведомость на запуск. [JSON](Pos/Adapters/Persistence/JsonGradebookRepository.cs)
  читает и пишет файл, а при чтении проходит через методы ведомости, поэтому
  битый файл не становится оценкой вне правил.
- [IFinalResultsExporter](Pos/Application/IFinalResultsExporter.cs): порт выгрузки
  уже посчитанного итога. CSV о нём знает [адаптер](Pos/Adapters/Export/CsvFinalResultsExporter.cs),
  домен - нет.
- [ConsoleApplication](Pos/Adapters/ConsoleUi/ConsoleApplication.cs): команды меню
  и текст для пользователя. [ConsoleInput](Pos/Adapters/ConsoleUi/ConsoleInput.cs)
  читает ответы из `TextReader` и одинаково работает с консолью и файлом.
- [Program](Pos/Program.cs): разбирает `--input` и `--data`, собирает DI-контейнер
  и выбирает хранилище.

Списки студентов, критериев и оценок возвращаются снимками.

## DDD

| Понятие | Где                                                                                                                                                                                              |
| --- |--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Единый язык | Студент, критерий, оценка, итог. Рубрикатор - набор критериев внутри ведомости, отдельного класса для него нет.                                                                                  |
| Сущность | `Student` и `Criterion`. Номер отличает двух людей с одним именем. Название критерия можно повторить, номер - нет.                                                                               |
| Объект-значение | `Evaluation`: номер студента, номер критерия и балл. Конструктор закрыт. При исправлении ведомость подставляет новое значение вместо старого. `GradeSummary` - снимок расчёта, его не сохраняют. |
| Инварианты | Балл внутри максимума, оценка только по известным студенту и критерию, один балл на пару, номера уникальны, максимум и вес больше нуля.                                                          |
| Агрегат | `Gradebook`. Эти правила относятся к одной ведомости, поэтому списки и оценки меняются только через неё.                                                                                         |
| Репозиторий | `IGradebookRepository`. Хранение лежит в адаптерах. Домен не знает, память это или JSON.                                                                                                         |
| Доменный сервис | `GradeCalculator`. Итог не поле студента и не поле оценки: он зависит от всего рубрикатора и текущего набора баллов.                                                                             |

## Архитектура

Выбраны Ports and Adapters. Зависимости направлены внутрь:

```
Program → Adapters → Application → Domain
```

Адаптеры дополнительно используют типы домена, когда показывают студента
или собирают ведомость из файла. `Domain` не ссылается ни на приложение,
ни на адаптеры.

| Папка | Ответственность |
| --- | --- |
| `Pos/Domain` | Модель, инварианты, расчёт итога. |
| `Pos/Application` | Сценарии и порты хранения и экспорта. |
| `Pos/Adapters` | Консоль, память, JSON, CSV. |
| `Pos/Program.cs` | Край программы: ввод, выбор хранилища, сборка DI. |

Слои разделены папками и пространствами имён; направление зависимостей поддерживается в коде.

## Паттерны GoF

| Группа | Паттерн | Где | Какую боль закрывает                                                                                                                                                 |
| --- | --- | --- |----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Порождающий | Фабрика | `Evaluation.Create` | Единственный способ получить оценку. Ведомость уже нашла студента и критерий, фабрика пускает только балл из диапазона. Тот же путь используется при чтении JSON.    |
| Структурный | Фасад | `PosFacade` | Меню не загружает ведомость, не вызывает калькулятор и не пишет CSV само. Один сценарий - один метод фасада.                                                         |
| Поведенческий | Стратегия | `IGradePolicy` | Калькулятор держит одну формулу. Правило решает, входит ли пропущенный критерий в сумму. Итог и промежуточный результат поэтому расходятся только на пустых клетках. |

Паттернов три. Округление до двух знаков делается в калькуляторе один раз,
отдельный декоратор был бы второй обёрткой над тем же процентом. Строитель
для критерия из номера, имени, максимума и веса ничего не собирает. Импорт
ведомости в требованиях нет, поэтому шаблонный метод для CSV и JSON не нужен:
JSON уже проходит через методы `Gradebook`.

**Сознательно ограничен рост меню:** команды перечислены в `switch`.
Новый пункт потребует ветки ввода, ведомость и калькулятор останутся прежними.
Для этого меню отдельные объекты команд были бы длиннее самого ввода.

## Тесты

В [GradebookTests](Pos.Tests/GradebookTests.cs):

- `InvalidScoreDoesNotReplaceAnExistingEvaluation` фиксирует, что −1 и 11 при
  максимуме 10 не затирают уже стоящие 8. Двенадцать баллов проверяют демо
  и консольный тест.
- `AnEvaluationRequiresAKnownStudentAndCriterion` не даёт оценить неизвестного
  студента или критерий вне рубрикатора.
- `CorrectingAnEvaluationDoesNotCreateASecondOneAndItCanBeCancelled` проверяет
  замену балла и повторную отмену.

В [GradeCalculatorTests](Pos.Tests/GradeCalculatorTests.cs):

- `MissingEvaluationCountsAsZeroOnlyInTheFinal` различает два правила на одной
  и той же ведомости, включая явно выставленный ноль.
- `RecalculationUsesTheCurrentRubricAndCurrentEvaluations` меняет балл,
  отменяет оценку, добавляет критерий и получает новый итог без сохранённой цифры.
- `ExtremeWeightsDoNotOverflowOrTurnAValidResultIntoZero` проверяет пропорции
  при очень больших и очень маленьких весах.
- `PercentIsRoundedToTwoDecimalPlaces` фиксирует округление 1/6 до 16.67.
- `MidpointPercentRoundsAwayFromZero` фиксирует 7 из 8 и 1 из 3: ровно 46,875%
  становится 46,88.

В [AdapterTests](Pos.Tests/AdapterTests.cs):

- `JsonRepositoryKeepsTheRubricAndCurrentEvaluationsBetweenInstances` сохраняет
  ведомость и читает её новым экземпляром репозитория.
- `InvalidJsonCannotLoadAnInvalidGradebook` не принимает пустую запись и оценку
  по отсутствующему критерию.
- `ConsoleShowsCurrentGradeAndExportsItAfterRejectingAnInvalidEdit` проходит
  меню до CSV и проверяет, что отклонённые 12 баллов не попали в файл.
